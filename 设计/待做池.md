# 待做池 —— 状态机的调度内核

> 2026-11-15 落的第一块。只做池本身，不接状态机、不读蓝图。

## 一、它解决的问题

状态机要的东西：**从池里拿一个当前能做的单元去跑，跑完再把下游放回池里。**

难点有三个，池都得兜住：

| 难点 | 池的处理 |
|---|---|
| 同一个单元被上游调起 2 次 | 池里**每个单元最多一条记录**（容量 1） |
| 第二条进不来怎么办 | **不录入**，返回一个 Promise，**上游挂起不结束**（背压） |
| 记录什么时候删 | 被取走并 `完成()` 之后才能再进 |

## 二、数据结构

```ts
type 单元标识 = { 蓝图: string; 单元: string }
type 待做项 = {
  蓝图: string
  单元: string
  还差: 单元标识[]    // 还差哪些上游（有序数组）
  标签: string | null // 被谁占着
}
```

**「还差」就是令牌**：

- 上游每激发一次 ⇒ 从下游的 `还差` 里删掉自己
- `还差` 删空了 ⇒ 这条变成**可执行**
- 池 `取()` 只取 `还差.length === 0 && 标签 === null` 的

⇒ 硬单元：`还差` 里是**全部**上游，要全删完
⇒ 软单元：录入时**不计上游** ⇒ `还差: []`，一进池就能取

## 三、API

| 方法 | 做什么 |
|---|---|
| `录入(项)` | 池里没有 ⇒ 进池，返回 `undefined`；池里已有 ⇒ 返回 Promise（上游挂起） |
| `取()` | 取一个真能做的，打上 `标签: '在跑'` |
| `完成(项)` | 整条删掉，唤醒等它腾位置的上游 |
| `到一次(蓝图, 单元, 上游)` | 从下游的 `还差` 里删掉这个上游，返回是否删到了 |
| `找(蓝图, 单元)` | 池里查这条 |
| `长度` / `有可执行` | 只读 |

**⚠️ 单元标识一律用 `{ 蓝图, 单元 }` 结构体，绝不拼字符串**——
单元名里可能有 `#`、`/`、`-`，任何分隔符都会被拆坏。
