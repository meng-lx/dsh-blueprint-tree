# 状态机要处理的所有维度

> 2026-11-15。把「种类 / 状态 / 标签 / 其他」四类东西摊开，方便看清哪些是真的耦合点。
> **待定项集中在第五节**，前面是现状。

---

## 一、种类（7 种，写在蓝图 json 的 `类型` 里）

| 种类 | 语义 | 状态机要做什么 | 谁算它的上游 |
|---|---|---|---|
| **开始** | 全项目唯一入口 | 被**外部投递**就进池（不算上游） | 无 |
| **结束** | 全项目唯一出口 | 跑到就**收工** | 所有指向它的 |
| **硬** | N 个上游到齐才跑一次 | `还差` 里是**全部**上游，删空才能跑 | 全部 |
| **软** | 任意一个上游到就跑一次 | 录池时 `还差: []`（**不计上游**） | 任意一个 |
| **选择** | 跑完看 `Start_<下游名>` 决定调谁 | 执行后读返回值，**只给 `true` 的下游**上令牌 | 全部 |
| **子蓝图** | 里面是另一张图 | **递归跑子图**，等子图跑完再放行下游 | 全部 |
| **循环向量** | 不是真单元，是一条"回边" | 见第六节 | 上游是选择单元，下游是它指回的那个 |

**关键差别只有三个**：

1. 要不要等齐（硬 / 软）
2. 要不要挑（选择）
3. 是不是另一张图（子蓝图）

---

## 二、状态（5 种，写在 `状态` 里）

| 状态 | 能不能执行 | 被调起时 |
|---|---|---|
| **正常** | ✅ | 正常跑 |
| **提醒** | ✅ | 正常跑（界面上提醒一下） |
| **报错** | ❌ | 断路 |
| **冻结** | ❌ | 断路 |
| **失效** | ❌ | 断路 |

**三个"断路"状态目前是同一个行为**：被调起时**直接结束，不做任何操作**。

⚠️ 但这里有个坑，见第五节问题 1。

---

## 三、标签（4 种，写在 `标签` 里）

| 标签 | 意思 | 状态机要做什么 |
|---|---|---|
| **无** | 普通 | 什么都不做 |
| **强制** | 输入不合规就报错 | 执行前由**执行单元**校验，不合规 ⇒ 拦 |
| **广播** | 同一个数据发给所有下游 | 调起下游时**不走 `Start_` 筛选**，全给 |
| **并发** | 允许多个实例同时在跑 | 池里这条不占用（可以多条） |

⚠️ 「并发」和「池容量 1」直接打架，见第五节问题 3。

## 四、四维叠加：实际有效的组合

不是 7×5×4=140 种，真正要考虑的是这些：

| 组合 | 有效吗 | 说明 |
|---|---|---|
| 开始 × 正常 × 无 | ✅ | 标准入口 |
| 结束 × 正常 × 无 | ✅ | 标准出口 |
| 硬 / 软 × 正常 / 提醒 × 无 | ✅ | 主力 |
| 硬 / 软 × 报错 / 冻结 / 失效 × 无 | ✅ | 断路 |
| 选择 × 正常 × 无 | ✅ | 挑路 |
| 选择 × 正常 × 广播 | ✅？ | 广播 = 全给，那和选择矛盾 |
| 子蓝图 × 正常 × 无 | ✅ | 递归 |
| 循环向量 × 正常 × 无 | ✅ | 回边 |
| 任意 × 报错 × 并发 | ❌ | 断路还并发没意义 |
| 开始 / 结束 × 任何标签 | ❌ | 锚点不该有标签 |
| 循环向量 × 任何标签 | ❌ | 它不是真单元 |

## 五、⚠️ 八个耦合点（需要你定）

### 1. 报错 / 冻结 / 失效的单元被调起 ⇒ 它的下游怎么办？

它不跑，那它的下游永远等不到它。

| 选项 | 后果 |
|---|---|
| **甲·透传**：把它收到的数据直接给下游 | 下游照跑，但少了一道处理 |
| **乙·整条停**：链路到此为止 | 下游永远卡住，需要"死锁报错"兜底 |
| **丙·下游也标失效** | 级联失效（你之前定过"运行时报错改失效并且传递"） |

⇒ **我猜你要的是丙**（跟"运行方法会自动落盘为失效状态"一致）。

### 2. 软单元能当选择单元的上游吗？

软单元"来一个跑一次"，跑完会**反复**给下游上令牌。

⇒ 如果下游是选择单元，它会**跑很多次**。
⇒ 这是允许的（`Start_` 每次都重新读），但要有心理准备。

### 3. 「并发」标签和「池容量 1」冲突

你说过池里每个单元**最多一条**。

⇒ 那"并发"的意思是：
- **甲**：允许同一条记录被**多个执行实例**同时消费（池里仍 1 条）
- **乙**：池里允许**多条**（容量变成 N）

⇒ 我猜是**甲**（"并发单元不会给上游背压"）。

### 4. 广播 + 硬单元：下游的 `还差` 怎么删？

广播 = 一次数据给**所有**下游。
⇒ 硬单元的下游 `还差` 里删的应该是**广播单元**这一个名字，而不是"每个下游各删一次"。

⇒ 也就是：**删「还差」是按上游名字删，不是按边删** ✅（现在就是这么实现的）

### 5. 循环向量：回边怎么回？

`选择 A → 循环1 → O`（O 是 A 的上游）。

⇒ 运行时：A 跑完给 `循环1` 上令牌 ⇒ `循环1` 跑完给 `O` 上令牌
⇒ 但 `O` 的 `还差` 里有**别的上游**（比如开始），早就删空了

⇒ **问题**：回到 `O` 时，`还差` 要**重新填满**吗？

| 选项 | 意思 |
|---|---|
| **甲**：重填 | `O` 要等它所有上游再来一遍（此时它等不到了 ⇒ 卡死） |
| **乙**：只删自己 | 只把 `循环1` 从 `还差` 里删掉（本来就是空的 ⇒ 直接跑） |

⇒ 用户之前说"循环部分要调优先级" ⇒ 这就是那个问题。

### 6. 子蓝图的入口/出口，在池里是什么？

子蓝图 = 黑盒，里外只通过它的「开始」「结束」交换数据。

⇒ 父图里它是**一个待做项**，但它内部**又是一个池**。
⇒ 是"嵌套池"还是"共用一个大池"？

⇒ 我猜：**嵌套**（子图有自己的池，跑完再回父图）。

### 7. `Start_` 没写的下游 ⇒ 默认调还是不调？

选择单元的返回值里写了 `Start_乙: true`，没写 `Start_丙`。

⇒ 丙调不调？

| 选项 | 意思 |
|---|---|
| **甲**：不调 | 只有明确写 `true` 才调 |
| **乙**：调 | 没写 = 默认调 |

⇒ 我猜**甲**。

### 8. 「强制」校验失败 ⇒ 报错、拦、还是跳过？

强制单元的输入不合规：
- **甲**：整个蓝图报错停
- **乙**：这个单元失败，下游标失效
- **丙**：跳过这个单元，直接给下游

⇒ 你之前定过"强制单元检测不合规就报错（兜不住）" ⇒ 甲。

## 六、运行时另外三个维度

| 维度 | 取值 | 影响 |
|---|---|---|
| **运行模式** | 正常 / 测试 | 测试模式出错不写盘、下游用旧数据继续 |
| **蓝图层级** | 主蓝图 / 子蓝图 | 子图有自己的池和锚点 |
| **块归属** | 插件层 / 蓝图层 / 方法层 | 状态机只碰前两层，方法层靠"执行单元" |

---

## 七、结论：真正要你拍板的只有六个

1. **断路后下游怎么办**（问题 1）
2. **并发标签怎么实现**（问题 3）
3. **循环回到 O 时 `还差` 重不重填**（问题 5）
4. **子图用嵌套池还是大池**（问题 6）
5. **`Start_` 没写的下游默认调不调**（问题 7）
6. **强制失败拦到哪一层**（问题 8）

其余（软单元、广播、硬单元删令牌）按现在实现就是对的。
